# Changelog

The public repository continues the version numbers of the code base it was built from, so the version notes in the code ("added in 0.3.7") stay meaningful. Up to 0.3.13 every upgrade after 0.2 was opt-in; since 0.4 the scenario scripts' default setting changes their results on purpose (below). The setting "0.2 published" still reproduces the 0.2 results exactly (check R0).

## 0.4.3 (25 November 2026)

This release brings the repository to version 0.4.3 of the code base (21 November 2026). The previous public version was 0.4.2.

**Default results change, on purpose.** The setting "0.2 published" (the Simulator's default) is unchanged and check R0 still passes. The scenario scripts' defaults change as follows:
- **The own 2023 SAM v1.1 is the default SAM** (`data/processed/InfinityGEM_SAM_PHL_2023_own_v1.1.csv`): v1.0 with the 2023 rice import duty corrected. The Bureau of Customs' certified 2023 rice collections (₱29.93 bn) are put on milled rice and corn alone, at PSA's 2023 customs value of those imports (an effective rate of 34.4%, against the statutory 35%), and palay, whose 2023 imports are seed, carries no duty. This settles the known issue of 0.4.2 (v1.0 had 48.1% on milled rice). `INFINITY_GEM_SAM_VERSION=1.0` gives v1.0 for every setting. A guard (`infinity_gem/rice_tariff.py`) refuses, in the 2026 rice-tariff scenarios, a SAM whose 2023 rice rate is off the customs-based rate, except the SAM files published before the fix, named with their checksums, so earlier results reproduce.
- **The public-works shock uses PSA's Q3 2026 national accounts** (`preshock/shock_paths.public_works()`, vintage `"q3"`: the first three quarters of 2026 as observed, the fourth at the year-to-date rate; `"oct14"`, the file of 14 October 2026, gives the earlier shock). PSA's table 0542B5BCNQ1 of the Q3 release is included.
- **The default setting is "0.4.3 recommended"**: the values of the earlier opt-in "0.4.2 candidate" (a re-fit of labour hoarding, the short-run consumption rule, the markup gap rule and the within-year oil pass-through; the short-run export elasticities; the estimated within-year pass-through of the peso into non-oil import prices), on SAM v1.1 with the Q3 public-works shock, with the policy rule of 0.4.1. Each named setting keeps the SAM and the shock vintage its numbers were computed on: "0.4.1 recommended", "0.4.2 candidate" and the earlier settings run on v1.0 with the 14 October shock (`INFINITY_GEM_SAM_VERSION` and `INFINITY_GEM_PW_VINTAGE` override every setting). The saved point of the re-fit is now included (`infinity_gem/calibration/refit_eval11_042c.json`), so the new default and the "0.4.2 candidate" both work in this repository (in 0.4.2 the candidate was unavailable here).

**New, opt-in** (no effect unless named): equivalent variation by household group, computed after a solve (`infinity_gem/welfare.py`, check EV1; an example in `scenarios/welfare_ev_example.py`); demography in labour supply, with population growth weighted by each age group's and sex's employment rate (`infinity_gem/demography.py`, check DM1; PSA's LFS table 0051B3FKEI5 of employment by sex and age is included); government financing closures in the static and dynamic models (`gfin=`, checks GF1 and GF2), government debt after a change in the deficit (`infinity_gem/debt.py`, check DB1) and foreign flows by institution (`infinity_gem/bop.py`), which read the Bureau of the Treasury's and the BSP's workbooks (not distributed; `data/raw/macro/README.md` says where to save them); the VAT part of the taxes on products (`infinity_gem/vat.py`, check VT1; it reads a table that the own SAM's builder writes); an electricity-fuels energy bundle and a carbon tax in the static and dynamic models (`energy_nest` with `fuels` and `sigma_f`, `carbon=`, shock key `ctax`; checks CT1 and CT2; the carbon intensity table holds GTAP values and is not distributed, so pass your own); PAMPh's own policy-rule coefficients and a variant estimated on Philippine data (`monetary.rule("pamph_annex3")`, `"pamph_estimated"`, check MP2: they read research files that are not in this release, so they are unavailable here, and they say so); the investment target refreshed with PSA's Q3 2026 release (check INV1).

**Checks.** The validation suite has 116 checks (102 in 0.4.2). Of the 14 new ones, GF1, EV1 and DM1 run here; R43 (the reference test of the central 2026 case under the new default, as R41), S14 (the own SAM v1.1's standalone rebuild test, as S13), INV1, PW1, VT1 and MP2 (they compare with saved results of development and research runs), CT1 and CT2 (the carbon intensity table), DB1 and GF2 (the Treasury's and the BSP's workbooks) and RGB (regional research) report NOT RUN, with the reason (`docs/STATUS.md`).

**Known issues**
- **No running check here computes the new default's central case.** Its reference test (R43) holds the case's results with its poverty counts, which this release does not publish, and the tests of SAM v1.1 (S14) and of the Q3 public-works vintage (PW1) need files that are not in this release. The pieces are in the code and the data, and the case runs with `scenarios/central_case_04.py` (its poverty rows need the FIES files).
- **The 0.4.3 default meets 8 of the 11 data targets it was scored on**, with a lower loss than 0.4.1 on the same data. The misses: the 2026 growth effect is milder than the data's (just outside its band), consumer-price inflation is just above its band, and the pattern of the shock across industries does not match the data's.

## 0.4.2 (21 November 2026)

This release brings the repository to version 0.4.2 of the code base (18 November 2026). The previous public version was 0.3.13.dev4; this one carries the changes of 0.3.13, 0.4.0, 0.4.1 and 0.4.2.

**Default results change, on purpose.** The setting "0.2 published" (the Simulator's default) is unchanged and check R0 still passes. The scenario scripts' defaults change as follows:
- **The own 2023 SAM v1.0 is the default SAM of the rice-split runs** (0.3.13): v0.9 with the taxes on fuel products set from 2023 collections (the petroleum excise, and VAT at the statutory rate on final and VAT-exempt fuel purchases) and coal mining's output set from PSA's 2023 gross value added of coal mining. `sam_variant="own-0.5"` gives v0.5, the earlier default. The SAM file and its input table, with the source of every input, are in `data/processed/`. Check S13 runs v1.0's standalone test (NOT RUN here, as S12).
- **The default oil series is public** (0.3.13): New Zealand MBIE's weekly Dubai crude price and importer costs of diesel and petrol (`preshock/shock_paths.py`, `DEFAULT_OIL_SOURCE = "public-mbie"`; check OL1), included under Figure.NZ's CC BY 3.0 NZ licence. The World Bank's monthly Dubai is the stated sensitivity (`"public-worldbank"`, November 2026 Pink Sheet, included). In this repository `"tracker"`, the weekly series of earlier runs, which may not be redistributed, reads the World Bank's Dubai and the EIA's US wholesale fuel prices instead, as in 0.3.13.dev4.
- **A scenario's peso amounts grow with the economy in the dynamic CGE** (0.3.13): `DynamicCGE(transfer_scaling="baseline")`, the new default, scales a scenario's transfers and other amounts with each year's baseline, as the SAM's own transfers are; `"legacy"` keeps the earlier behaviour, and "0.2 published" pins it. Check TS1.
- **The scenario scripts' default setting is "0.4.1 recommended"** (0.4.0 and 0.4.1). "0.4 recommended" is "0.3 recommended" plus, in the short-run years of dynamic runs on the own SAM v1.0 with the hybrid closure, markup pricing of non-farm home sales with stickiness by sector for price falls, a margin floor, slack from the LFS natural rate of unemployment, a smooth employment cap, labour hoarding, a short-run consumption rule and a partial within-year oil pass-through, at a point fitted to 2026 data (it meets 8 of 11 data targets), and a central-bank rule of the PAMPh type inside every path (theta 1.5; gaps against the no-shock path). "0.4.1 recommended" adds a ceiling of 1 on the markup gap rule's pass-through and takes the rule's expected-inflation term from last year's inflation gap. Every value and its source is in `infinity_gem/settings.py` (`OPTION_C_04`, `OPTION_C_041`). "0.4 recommended" and "0.3 recommended" stay available by name (`INFINITY_GEM_SETTING`); 0.4 is defined only on the own SAM v1.0; the static CGE and the Simulator are unchanged.
- **FIES 2025 is the default base of the poverty microsimulation** (0.4.2; `infinity_gem/fies_base.py`): PSA's FIES 2025 public-use file (Volume 1) with PSA's 2025 poverty thresholds by province and urban/rural; `INFINITY_GEM_FIES_BASE=fies2023` or `base="fies2023"` gives the FIES 2023 base of every figure computed before. Neither survey is distributed (`data/raw/fies/README.md`). The LFS earnings link and the Simulator stay on FIES 2023.

**New, opt-in** (no effect unless named): an engine fallback for a year whose switching employment cap does not settle (that year alone is re-solved with the smooth cap; check EF1); a ceiling on the markup gap rule's pass-through (MC1); conventions of the policy rule (targets by quarter, an expected-inflation term from last year, observed decisions; MT1); a short-run private-investment accelerator (ACC1); a short-run export (CET) elasticity (CET1); an estimate of the within-year peso pass-through into non-oil import prices for `sr_erpt` (ERP1); the setting "0.4.2 candidate", which reads a saved re-fit result that is not in this release, so it is unavailable here; DSGE milestones 27-30 (`research/dsge/`: wage indexation, dollar pricing of exports, the oil-supply responses of local projections as a benchmark, an oil-system prior).

**Checks.** The validation suite has 116 checks (85 in 0.3.13.dev4). Of the new ones, TS1, OL1, MT1, MC1 and ACC1 run here with their standalone tests; FB1 and R41F (FIES 2025), S13 (as S12), R4, R41 and R42 (the reference tests of the central 2026 case, not in this release), EF1, CET1, IS1 and ERP1 (they compare with saved results of earlier runs), RG1 (regional research) and RB1 (a research batch) report NOT RUN, with the reason (`docs/STATUS.md`). Check X3 runs the DSGE tests of milestones 27 and 28 except one each (T27f, T28e), and skips milestone 30's: they need the saved particle cloud of a long estimation run and report themselves not run without it.

**Known issues**
- **The rice import duty in the own SAM v1.0.** The SAM's import tax on milled rice is 48.1% of the value of milled-rice imports, against a statutory tariff of 35% in 2023. The difference is under review (a diagnostic is running). Results that depend on the rice tariff or on rice imports should be read with this in mind; a correction, if needed, will come as a new SAM version.
- **The 0.4 settings meet 8 of the 11 data targets they were fitted to.** The open misses: exports fall more than the 2026 data show, the pattern of the shock across industries does not match the data's, and the investment target is on a different basis; the peso's pass-through to consumer prices is above the central bank's estimates. A re-fit under the 0.4.1 rule has not been made yet (the fitted values are 0.4's).

## 0.3.13.dev1 (23 October 2026)

- **A short-run consumption rule** (opt-in; check CS1): `DynamicCGE(sr_consumption={"htm": lam})`, with lam between 0 and 1. In the hybrid closure's short-run years, the share lam of household spending follows disposable income at the baseline saving rates (hand-to-mouth households) and the rest keeps its baseline real value (households that smooth their consumption). The rule is met by the year's saving-rate adjustment, one factor for every household, solved together with the wage curve and re-solved whenever the employment cap changes regime. With the option off (the default) or lam = 1 the results are unchanged. `scenarios/consumption_rule_2026.py` applies it to the central 2026 case.
- **Research DSGE, milestone 25:** the capital model with a flexible-price energy share of the CPI (`research/dsge/soe_htmkf.py`; its test `test_milestone25.py` runs in check X3), and the same model with sticky (Calvo) wages (`soe_htmkw.py`; its test `test_milestone25b.py` is run by hand). `estimate_rot.py` takes `model=htmkf` and `model=htmkw`; `htmk_theta.py` takes `model=htmkf` and a `pattern=` option that scores saved sampler output.
- The validation suite has 75 checks. With default settings the model still reproduces version 0.2 exactly (check R0).

## 0.3.13.dev0 (22 October 2026): first public build

The development copy, published for outside review under the name Infinity GEM (by Paolo Navata; it extends pystdcge, https://github.com/psnavata-alt/pystdcge); new since 0.3.12: markup pricing in short-run years (opt-in; check MK1). Compared with the code it was built from: the package is renamed `infinity_gem`; data that may not be redistributed are left out (`docs/STATUS.md`), and the checks that need them report NOT RUN; PSA's 2018 input-output and supply-use tables are included, so the input-output checks run; the 2026 oil-shock sizes are measured from public monthly series (World Bank Pink Sheet, EIA STEO) instead of a compiled weekly tracker; comments and report text are worded neutrally (no people, organizational units, working documents or planning lists), with the code unchanged.
